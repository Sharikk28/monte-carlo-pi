# Обчислення числа π методом Монте-Карло

Вебзастосунок, backend якого обслуговує трудомісткі запити користувачів і розподіляє їх між кількома серверами.

Користувач задає кількість випадкових точок (до 30 мільйонів). Сервер кидає ці точки у квадрат, рахує, яка частка потрапила в коло, і за цією часткою обчислює π. Що більше точок, то точніший результат і довше обчислення.

## Можливості

- Реєстрація і вхід користувачів, робота через HTTPS.
- Обмеження трудомісткості: кількість точок і час обчислення однієї задачі.
- Показ ходу виконання: відсоток і проміжне значення π.
- Історія задач, перегляд стану, скасування, запуск нових задач.
- Балансування навантаження: Nginx розподіляє запити між двома API-серверами, задачі розподіляються між кількома серверами обчислень.
- Черга задач із місцем у черзі та приблизним часом очікування.
- Автоматичний запуск додаткових серверів обчислень при навантаженні (від 2 до 5) і їх зупинка після простою.
- Повернення задачі в чергу, якщо сервер обчислень перестав відповідати.
- Панель адміністратора: стан серверів, активні задачі, навантаження.

## Технології

| Частина | Технологія |
|---|---|
| Load balancer, HTTPS | Nginx |
| API | Python, Flask, gunicorn |
| Сервери обчислень | Python |
| База даних і черга задач | PostgreSQL |
| Автомасштабування | Python, Docker SDK |
| Frontend | HTML, JavaScript |
| Запуск | Docker Compose |

## Архітектура

```
                 Браузер
                    │ HTTPS
                    ▼
                  NGINX            load balancer, роздає frontend
               ┌────┴────┐
             api1      api2        Flask: авторизація, задачі, адмін-панель
               └────┬────┘
                    ▼
               PostgreSQL ◄─────── scaler (автомасштабування)
                    ▲
     ┌──────────┬───┴──────┬──────────────┐
  worker1    worker2   worker-auto-1 ... worker-auto-3
```

Докладний опис елементів і зв'язків між ними: [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Потрібен встановлений і запущений [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
git clone https://github.com/ВАШ_ЛОГІН/monte-carlo-pi.git
cd monte-carlo-pi
docker compose up -d --build
```

Після запуску сайт доступний за адресою https://localhost.

Сертифікат самопідписаний, тому браузер покаже попередження: «Додатково» → «Перейти на сайт localhost».

Адмін-панель: https://localhost/admin.html. Логін і пароль адміністратора задаються в `config.env` (`ADMIN_USER`, `ADMIN_PASSWORD`).

Зупинка:

```bash
docker compose down
```

## Налаштування

Усі ліміти зібрані у файлі `config.env`.

| Змінна | Значення | Зміст |
|---|---|---|
| `MAX_POINTS` | 30 000 000 | максимальна кількість точок в одній задачі |
| `MAX_SECONDS` | 60 | ліміт часу однієї задачі, секунд |
| `MAX_ACTIVE_PER_USER` | 5 | активних задач на одного користувача |
| `MAX_QUEUE` | 20 | максимальна довжина черги |
| `MAX_WORKERS` | 5 | максимальна кількість серверів обчислень |
| `IDLE_SECONDS` | 30 | час простою, після якого додатковий сервер зупиняється |

Паролі й ключі в `config.env` та сертифікат у `nginx/certs` призначені лише для локального запуску. Перед розгортанням на справжньому сервері їх треба замінити.

## Структура проєкту

```
├── docker-compose.yml      опис усіх контейнерів
├── config.env              ліміти й налаштування
├── nginx/                  конфігурація балансувальника, сертифікат
├── db/init.sql             таблиці бази даних
├── api/                    Flask API
├── worker/                 сервер обчислень і алгоритм Монте-Карло
├── scaler/                 автомасштабування
└── frontend/               сторінка користувача й адмін-панель
```
